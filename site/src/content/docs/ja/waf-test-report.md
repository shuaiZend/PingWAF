## 結果サマリー

バージョン 0.32.4、テスト日 2026-11-02、公開コーパス [chaitin/blazehttp](https://github.com/chaitin/blazehttp)：生 HTTP メッセージ 33 877 件（悪意ある 658 / 正常 33 219）。

| 指標 | 結果 |
| --- | --- |
| 実効基準の検知率 | 96.6%（616/638） |
| 全量基準の検知率 | 93.8%（617/658） |
| 正常トラフィックへの影響 | 0.06%（19/33 219） |
| 正確率 | 99.82% |
| 静的ティアの p95 | ≤ 2 ms |

どの数字を使うべきか？96.6% の分母は 638 です：悪意ある 658 件のうち、プロキシ側 WAF には判定できない 20 件を除外しています — `Content-Length` / `Transfer-Encoding` のない POST/PUT 19 件（RFC 7230 によりリクエストボディは空）、および URL fragment にペイロードを隠した 1 件（HTTP パーサーはリクエストラインを構築する前に fragment を剥離します）。全量基準（93.8%）は参考として残しています。

## 今回の改善

1. 中国語の `and 1=1` 検索・計測値を SQLi と判定しないよう修正（7 件）、`.github` パスを dotfile 探査として扱わないよう修正（1 件）— 4 ティアの検知数は不変（396/473/500/617）で、正常サンプルへの影響は 12/20/12/27 から 4/12/4/19 に減少。
2. 圧縮攻撃ボディのエンドツーエンド対応：悪意ある gzip 8/8 をブロック、良性 2/2 を通過。
3. チャレンジ（503）とブロック（403）を分けて集計。

## 数字の出所

release ビルド、静的 TOML データプレーン（`pingwaf -c`、オリジンはモック）；生 33 877 件のメッセージを生の HTTP/1.1 ソケットで loopback 上にバイト単位で再生、16 並列・5 ms 間隔；検知は 403 ブロックページと 503 チャレンジページのみを数え、プロトコル層・メソッド層の拒否は数えません；エンジンのユニットテスト 250 件が合格；すべての数字は次節のコマンドで再現できます。

## 再現

```bash
git clone --depth 1 https://github.com/chaitin/blazehttp /tmp/blazehttp
export BLAZEHTTP_ROOT=/tmp/blazehttp
cargo build --release --bin pingwaf --features=full
./tools/waf-bench/run_suite.sh --conf tools/waf-bench/conf/level-strict-body.toml --suite full --group strict-body --out results/0.32.4/strict-body --concurrency 16 --delay-ms 5
```
